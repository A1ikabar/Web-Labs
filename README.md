# Лабораторная работа №2
## Тема: Проектирование и реализация RESTful API

## Описание проекта

В данной лабораторной работе реализован RESTful API с использованием фреймворка **Django**, базы данных **PostgreSQL** и контейнеризации **Docker**.

API позволяет работать с сущностью **Work** (работа автора).
Пользователь может:

- создавать новые записи
- получать список работ
- получать одну работу по ID
- изменять данные работы
- удалять работу (реализовано мягкое удаление)

Также реализована **пагинация**, чтобы получать данные по страницам.

# Запуск проекта

## 1. Клонирование репозитория

```bash
git clone <repository_url>
cd Web-Labs
```

## 2. Запуск базы данных

Запустить контейнер PostgreSQL:

```bash
docker compose up -d
```

Docker создаст контейнер с базой данных.

## 3. Активация виртуального окружения

Windows:

```bash
.\.venv\Scripts\activate
```

## 4. Применение миграций

Если база данных пуста, нужно выполнить:

```bash
python manage.py migrate
```

Это создаст таблицы в базе данных.

## 5. Запуск сервера

```bash
python manage.py runserver 4200
```

После запуска сервер будет доступен по адресу:

```text
http://127.0.0.1:4200
```

# API

## Список эндпоинтов

### Получить список работ

```text
GET /works
```

Пример:

```text
http://127.0.0.1:4200/works
```

### Получить одну работу

```text
GET /works/{id}
```

Пример:

```text
GET /works/uuid
```

### Создать новую работу

```text
POST /works
```

Пример запроса:

```json
{
  "title": "Моя лабораторная работа",
  "description": "Описание работы",
  "author_name": "Ксения"
}
```

Ответ:

```text
201 Created
```

### Полное обновление работы

```text
PUT /works/{id}
```

Пример:

```json
{
  "title": "Обновленная работа",
  "description": "Новое описание",
  "author_name": "Ксения"
}
```

### Частичное обновление

```text
PATCH /works/{id}
```

Пример:

```json
{
  "title": "Новое название"
}
```

### Удаление работы

```text
DELETE /works/{id}
```

Удаление реализовано через Soft Delete.

Запись не удаляется из базы данных, а помечается как удалённая.

# Пагинация

API поддерживает пагинацию.

Параметры запроса:

```text
page
limit
```

Пример:

```text
GET /works?page=1&limit=5
```

Ответ содержит:

```text
meta.total
meta.page
meta.limit
meta.totalPages
```

# Soft Delete

Удаление реализовано через поле:

```text
deleted_at
```

При удалении запись не удаляется физически из базы данных, а просто получает дату удаления.

Это позволяет:

- сохранить историю данных
- избежать случайной потери информации

При запросе списка работ удалённые записи не возвращаются.

# HTTP методы

В API используются следующие методы:

| Метод | Описание |
|---|---|
| GET | получение данных |
| POST | создание записи |
| PUT | полное обновление |
| PATCH | частичное обновление |
| DELETE | удаление |

# Коды ответов

| Код | Значение |
|---|---|
| 200 | успешный запрос |
| 201 | объект создан |
| 204 | объект удалён |
| 400 | ошибка запроса |
| 404 | объект не найден |

# Миграции

Миграции используются для создания структуры базы данных.

Создание миграции:

```bash
python manage.py makemigrations
```

Применение миграций:

```bash
python manage.py migrate
```

# Тестирование API

API можно тестировать через:

- Postman
- curl
- любой HTTP клиент

Пример curl запроса:

```bash
curl -X GET http://127.0.0.1:4200/works
```

# Функциональность

В проекте реализовано:

- все HTTP методы работают корректно
- реализовано мягкое удаление (Soft Delete)
- реализована пагинация
- удалённые записи не возвращаются в GET запросах
- присутствует валидация данных
- используются миграции базы данных
- проект разворачивается через Docker
